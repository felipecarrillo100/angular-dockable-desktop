# M7 — Minimise, taskbar, live previews · **PASS**

**Gate:** `npm run gate -- M7` (standing gate, M7 rules, browser gate). 402/402 unit tests.

## What exists

- **`ndd-taskbar`** has three modes:
  - `always`: a permanent strip;
  - `compact`: present only while something is minimised;
  - `autohide`: an 8 px peek strip that expands on hover and flashes open for 2 s when a panel
    is minimised.

  It shows scroll arrows past four icons. On touch, the first tap previews, the second
  restores, and a long press requests a context menu (the `taskbarContextMenu` output, with an
  `{ panelId, event }` payload). The built-in taskbar menu lands in M8.
- **`ndd-taskbar-preview`** is **the live panel itself**, moved into a scaled box:
  - it takes the panel on `ngAfterViewInit` with `refocus: false`, so hovering never steals the
    caret;
  - it gives the panel back on destroy **only if it still holds it**, since a restore both
    closes the preview and gives the panel a slot, in no guaranteed order;
  - panels with `disableLivePreview` get a letter tile instead.
- **`[nddPortal]`**: moves an element to `document.body` for its lifetime. It is the Angular
  counterpart of `<Teleport to="body">`, needed because the glassy taskbar's `backdrop-filter`
  makes it the containing block even for `position: fixed` descendants.

## Browser gate (real Chrome, zoneless **and** zone.js)

- **Live preview:** hovering the icon with a real mouse opens a preview containing **the same
  node**:
  - there is exactly one copy;
  - the video keeps playing inside the preview (`currentTime` advances, not paused);
  - WebGL is alive;
  - the thumbnail is really scaled on screen (its on-screen width is smaller than its laid-out
    width).
- **D11:** the thumbnail is hit-testable, but the live panel inside it is inert, and a real
  click on the thumbnail restores the panel into its slot and closes the preview.
- **D3 / D4:** `openPanel` on a minimised panel returns it to its own group (R), and publishes
  `panel:restored` and `layout:changed`.
- **Survival:** the panel is created once throughout.

**Negative control** (`m7.mjs --control`, run by M7's rules): rdd 6.2.0's D11 defect is
modelled as the preview being dead to the pointer except its header row. It is rejected with
"the thumbnail is not hit-testable", a failed restore, and an empty slot.

## Findings

1. **The first D11 control did not model the defect.** `pointer-events: none` on the frame
   alone lets the click fall through to the preview's own container, which restores, so the
   gate passed it. The control now makes the preview inert except its header, as vdd describes
   rdd, and the gate rejects it.
2. **Lint caught an output named `close`.** An output named like a native DOM event is also
   triggered by that DOM event. It is renamed `closeRequest`.
