# M4 — Desktop grid + zero unmount · **PASS**

**Gate:** `npm run gate -- M4` (standing gate, M4 rules, browser gate). 330/330 unit tests
across 18 files.

## What exists

- **`<ndd-desktop>`**: the workspace host. Skin, colour scheme and animation state are mirrored
  onto `<html>`, and `--ndd-z-base` is wired from `zIndexBase`. It runs the stylesheet and
  zero-height diagnostics in development only, and does its browser work behind
  `isPlatformBrowser`.
- **`ndd-workspace-grid`** (recursive) and **`ndd-leaf-group`**: branches with pointer-drag
  dividers, and tab groups (`role="tablist"`) with close buttons and an "empty group" close
  button. Selected is distinguished from globally active, which is the D2 invariant.
- **`PanelHost`**: the only place a panel is created or destroyed. It uses
  `createComponent({ hostElement })` on a library-owned element and `appRef.attachView`. It
  handles lazy panels (a placeholder, then the real component), and panel data arrives as the
  component's **own declared inputs** (`reflectComponentType`), by name or alias. Undeclared
  keys are skipped without NG0303.
- **`[nddPanelSlot]`**: moves a panel in on init, and parks it on destroy unless another slot
  already holds it (ADR 0002 addendum).
- **`injectPanel()` → `PanelRef`**: signals for `isActive`, `isMinimized`, `isFloating`,
  `containerType`, `size`, `dirty` and `title`; actions; and registrations disposed via
  `DestroyRef`. Standalone-safe.
- **`PanelDomCache`**: M0's persistence module with vdd's `hostOf`, `release`, sizes and
  `dispose`.
- **`injectColorScheme()`**, and **`ndd-icon`** (component / `TemplateRef` / class list).
- **Stylesheet:** vdd's inline grid layout moved into rules (D12), plus rules for the three
  elements only the port renders.

## Browser gate (real Chrome, zoneless **and** zone.js)

Panel h1, holding WebGL, a playing video, a scrolled list, a focused input and a clicked
counter, is driven through:
- a tab switch away and back;
- a split into the other group;
- a **real pointer drag** on the split divider;
- a re-dock;
- a minimise and restore.

After every step the gate asserts:
- the panel was created once and never destroyed;
- there is one copy of its DOM, and it is the same node;
- WebGL is alive;
- the video keeps advancing;
- scroll, focus, caret and component state are intact.

In the "tab away" step it also asserts that a background tab has no slot, and in "minimise"
that the panel is parked in the store.

## Findings

1. **A split divider's midpoint is a junction.** After a split, the nested divider crosses the
   parent's at exactly half height, and there the nested divider's enlarged hit area wins
   (probed with `elementFromPoint`). This is harness, not library: it is inherent in crossing
   dividers and matches vdd's stylesheet. The gate grabs the divider a quarter of the way down.
2. **jsdom makes every desktop report "stylesheet not loaded"**, which is correct, because it
   never loads CSS. `test/setup.ts` declares the sentinel, as a real app's stylesheet does; the
   M12 diagnostics suite will remove it to prove the warning.
3. **Non-vacuity must reach templates.** A component's behaviour is mostly its template and
   `computed()` fields, which method stubs never touch. The stubber now blanks inline
   templates (and their `imports`, or extended diagnostics fail the build). The selftest pins
   this.

## M4's own rules (`scripts/gates/m4.mjs`)

1. `createComponent` appears only in `panel-host.ts`; no `ViewContainerRef` is used for
   panels; panels are created on the library-owned element and attached to `ApplicationRef`.
2. Modern Angular only. None of:
   - `@Input` / `@Output` / `@HostBinding` / `@HostListener`;
   - decorator queries;
   - `NgModule`, or `standalone: false`;
   - non-OnPush change detection;
   - `*ngIf` / `*ngFor`.
3. No static `style="…"` and no host `style` (D12).
4. The promise tests passed.
5. Non-vacuity. Tests failing when each module is stubbed:
