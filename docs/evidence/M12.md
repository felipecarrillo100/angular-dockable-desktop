## What exists

- **`injectPanelContribution(() => contribution)`** takes a *getter*, read in an effect.
  - It publishes at construction.
  - It republishes on the effect's first run, which sees the inputs, and again whenever what
    the getter reads changes.
  - It publishes before withdrawing and is withdrawn with the component.
  - Outside a panel it warns and does nothing.
- **`injectActiveContribution()`** returns the workspace's `activeContribution`, derived from
  `activePanelId` only (D2). **`injectMergedToolbarItems()`** and **`injectMergedSidebarTabs()`**
  are `computed`s over the plain `merge*` functions.
- **i18n, direction and classes:** `workspace.format`, `messages`, `classes`, `dir()` and
  `isRtl()` already existed and are now ported and tested. A formatter that reads a signal
  relabels the chrome live.
- **Diagnostics:** the stylesheet sentinel names Angular's fix (the `angular.json` `styles`
  array), and the zero-height warning names where the height chain breaks. Both are
  development-only.

## Production bundle (M12 rule 8)

The standing gate builds the playground in production. The M12 rules grep that bundle for eight
dev-only messages: the stylesheet sentinel, the zero-height warning, the `showCloseButton` and
empty-tab warnings, "outside a panel", layout repair, "not registered", and block-stretch.
- None may appear.
- The real runtime error "Could not load panel" *must* appear, which proves the grep is reading
  the library's code.
- **Negative control:** the same playground built with `--configuration development` must
  contain all eight messages.

## Findings

1. **Every dev-only message was shipping in production.** The library guarded dev code with a
   helper, `const devMode = () => typeof ngDevMode === 'undefined' || !!ngDevMode`. The CLI
   defines `ngDevMode` as `false`, but a *call* to a helper does not constant-fold, so all
   eight messages (and the warning code around them) were in the production bundle.
   - Every site now uses the guard inline, which is the form Angular's own code uses.
   - Workspace warnings are guarded at each call site, so their message literals fold as well.
     The layout-repair messages in `core/serialize.ts` are guarded where they are built.
   - Rule 6 forbids the helper anywhere in the library; rule 8 checks the result in the real
     bundle.
2. **The first `injectPanelContribution` skipped the effect's first run** and published only at
   construction, before inputs are set. So `act-${panelId}` published as `act-` (7 failures on
   the first run). The first effect run now republishes.
3. **The "never publishes nothing" test was weaker than vdd's at first.** It patched the store
   after the panel had its first registration, so the withdrawal that could open the gap was
   unpatched and a reversed order would still pass. It now instruments before the panel opens,
   and a deliberate reversal in the library fails it.
4. **The browser RTL check first assumed tab order.** Restoring a minimised panel appends it to
   its group, so the order is `[b, a]`. The check now reads the leaf's actual order.
