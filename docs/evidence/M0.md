## What was asserted

The test panel holds a live WebGL context, a playing video, a scrolled list, a focused input
with a caret, a 50 ms timer writing a signal, a CSS animation and an iframe. It was driven
`leafA → leafB → floating → hidden → leafA → REBUILD → leafB → floating → REBUILD → leafA`.
`REBUILD` re-keys the host block, so Angular destroys and re-creates **every host element
while the panel is inside one**, which is stricter than vdd's spike.

After every step:
- one mount and no unmounts;
- exactly one copy of the panel's DOM;
- the same DOM node object;
- the panel is connected;
- the WebGL context is not lost.

On visible steps, additionally:
- video time never went backwards;
- `scrollTop === 220`;
- focus is back on the input, with the caret at 4 and the value intact.

Once per configuration:
- the element-injector token reached the panel;
- the scheduler is the one requested (`window.Zone` present exactly in zone runs);
- a timer-driven signal and a `ComponentRef.setInput()` both render **while the panel sits in
  the hidden store**;
- restoring an inactive panel does not steal focus from the active one.

These run in four configurations: two strategies × zoneless / zone.js.

**Characterised, not asserted:** the iframe reloads on re-parent (as in vdd; not
preventable), and CSS animations keep running.

## Non-vacuity

The gate was also run against two deliberately wrong configurations, and must reject both:

- `inline` renders panels declaratively inside each host, which is the naive Angular
  approach. Rejected with 27 failures: a re-mount on every move and node identity changed.
- `nopreserve` uses the chosen strategy with scroll/focus restoration off. Rejected with 16
  failures.

## Gate attempts

| Run | Result | Cause |
|---|---|---|
| 1 | FAIL, focus only, every config | **Implementation.** Chrome fires `focusout` synchronously during removal while `isConnected` is still true, so the live focus tracker erased the record mid-move |
| 2 | PASS | Own moves suppress the handler; foreign detaches are judged one microtask later |
| 3 | PASS + selftest PASS | Negative controls added |

## Decision

The primary strategy is `createComponent({ hostElement })` + `appRef.attachView`. See
[ADR 0002](../decisions/0002-zero-unmount-via-host-element.md) for the rationale and the
four findings that carry into M4.
