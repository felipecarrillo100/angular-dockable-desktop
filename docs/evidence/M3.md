# M3 — The workspace store · **PASS**

**Gate:** `npm run gate -- M3`. 284/284 tests across 15 files.

## What exists

- **`Workspace`** (`src/lib/workspace/workspace.ts`): vdd's 958-line store, action by action,
  on one immutable `WritableSignal<WorkspaceState>`. It has read-only views (`state()`,
  `gridRoot()`, `panels()`, `activePanelId()`, …), and every mutation is a method. The rules
  specific to Angular:
  - **Every read inside an action is `untracked`.** An action called from an `effect()` never
    makes that effect depend on the store. This is pinned by a test, and by M3 rule 3 (no
    tracked `_state()` read outside the computed views).
  - **Dev-mode deep freeze** of published state stops at panel `props`, so "state is
    read-only" holds without a proxy and application objects are never frozen.
  - **`subscribe()` auto-disposes** through `DestroyRef` when called in an injection context,
    the same contract as `takeUntilDestroyed()`. It also returns the unsubscribe function.
- **`createWorkspace(config)`** works before bootstrap. **`provideDockableDesktop(config |
  workspace)`** returns plain `Provider[]`, so it works in `bootstrapApplication` *and* in a
  component's `providers`, which gives two independent workspaces on one page. A
  config-created workspace is disposed with its injector; a passed instance is owned by its
  creator. **`injectWorkspace()`** is `inject(Workspace)` with a directed error.
- **Registry** with lazy panels: `{ loadComponent: () => import(…) }`, the router's shape.
  `resolve()` loads once, shares concurrent loads, and unwraps `default` exports.
- **Signal ports** of `overlays`, `contributions`, `toolbar-state` and `context-menu`, plus
  the toolbar/sidebar type modules. `NddIcon = Type | TemplateRef | string` (a CSS class
  list), so no icon library is imposed (ADR 0007). Their own suites land at M8–M12.

## Findings

1. **The CLI's unit-test builder ran the suite on zone.js.** It does so whenever zone.js is
   installed in the workspace (it is, for the zone-build playground). TestBed had a real
   `NgZone` and no automatic change detection, the opposite of what this library is designed
   around. `test/test-providers.ts` now supplies `provideZonelessChangeDetection()` (probed:
   `NoopNgZone`, and a signal change re-renders with no manual `detectChanges()`). zone.js
   remains covered by every browser gate (ADR 0006).
2. **Porting a store's reads from a proxy to a signal is not purely mechanical.** Three
   conversion traps were caught and fixed in the port script:
   - `PanelInfo.state` is not the workspace's `.state`;
   - `typeof w.state().x` is not a type;
   - `expect(…).state)` after a `)` was missed.

## M3's own rules (`scripts/gates/m3.mjs`)

1. Every placement action (12 of them) ends in `this.resolveActive()`.
2. `activePanelId` is a top-level key of a `this.set({…})` patch only in `resolveActive`,
   `focusPanel` (the documented minimised-focus case) and `loadLayout`.
3. There is no tracked `this._state()` read outside the computed views.
4. There is no module-level `let`/`var` in the store's modules.
5. The milestone's promise tests passed, and all 10 fixtures round-trip.
6. Non-vacuity.

Rules 1–3 were each **proven to fail** by planting a violation in a copy of the source:
- a second `activePanelId` write;
- a `dockPanel` without `resolveActive`;
- a tracked read in `isOpen`.

Each was rejected for its stated reason.
