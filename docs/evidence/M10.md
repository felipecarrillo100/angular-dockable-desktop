# M10 — Modals, side panels, confirm, toasts, dirty state and guards · **PASS**

**Gate:** `npm run gate -- M10` (standing gate, M10 rules, browser gate). 669/669 unit tests.

## What exists

- **`<ndd-modals>`** renders the modal stack and supplies the library's unsaved-changes
  question. Mount none and a dirty close *refuses*: asking needs somewhere to render.
  **`<ndd-side-panels>`** renders the two drawers, and `sides` narrows it to one edge. Both are
  `display: contents` hosts over `position: fixed` chrome, so where they sit doesn't matter.
- **One host implementation** (`createOverlayHost`), shared by the modal host and the drawer
  host:
  - the close sequence, with its question;
  - the title's dirty asterisk;
  - Escape routing (the topmost modal answers; a drawer answers only when no modal is open);
  - the `injectPanel()` contract for the content: `containerType` is `modal`, `left-panel` or
    `right-panel`, and `setTitle`, `setIcon`, `setDirty` and `close` are all live.

  Content receives only the inputs it declares (no NG0303), with the injected `panelId` last.
  A modal is `role="dialog"` with `aria-modal` and an accessible name.
- **`injectModals()`**: `stack`, `topmost`, `open`, `close` and `closeAll`. **`open()` returns
  an `NddModalRef<R>`**, shaped like Material's `MatDialogRef`:
  - `afterClosed()` resolves with what the content passed to **`injectModalRef<R>().close(r)`**;
  - it resolves `undefined` for every other way out (Escape, ×, backdrop, `closeAll`);
  - `requestClose()` goes through the guard and the question.

  The store gained `close(id, result)` and `whenClosed(id)`; every removal path settles its
  waiters, so a ref can never await forever.
- **`injectSidePanels()`** mirrors vdd's `useSidePanels`. Opening an occupied drawer is async and
  resolves `null` when the occupant's guard refuses.
- **`<ndd-confirm>`** focuses its confirm button, and `onSettled` fires exactly once however it
  goes away.
- **Toasts:**
  - `toast()`, `toast.info/success/warning/error/dismiss/promise`, and `resetToasts()`;
  - the queue is a **module-level signal**, so it works from services, interceptors and guards,
    and two containers show the same toasts;
  - **`NddToaster`** is the same API as an injectable;
  - **`<ndd-toasts>`** is portalled to `document.body`, with `maxVisible` as a `computed()`
    slice, pause on hover, a progress bar, an adapter, and the `max-height` re-sync (T13).
- **`injectPanel().trackDirty(source, options?)`** is an effect on the panel's own injector. It
  keeps the dirty flag in step with any signal, typically a **Signal Forms** form's `dirty()`,
  and `options` may be a getter so the question says what is wrong *now*. It works the same in a
  tab, a window, a drawer and a modal.

## Browser gate (real Chrome, zoneless **and** zone.js)

The playground mounts `<ndd-side-panels>`, `<ndd-modals>` and `<ndd-toasts>`, and gained an
`editor` panel: a Signal Forms form with `required(name)`, tracked with `trackDirty`.

- **Dirty:** typing into the field with the real keyboard marks the tab `*`.
- **The question:** a real click on the tab's × opens it. It is on top (hit-tested at the
  window's centre) and focus is on its confirm button.
  - **Escape** refuses: the panel stays open with its text intact.
  - **"No"** refuses.
  - From a **floating window's ×** the question appears too, and **"Yes"** closes the panel.
- **Drawer:** it sits at the left edge, 400 px wide. Typing makes its title `Drawer *`; Escape
  asks, and "Yes" closes it.
- **Stack:** the second modal is on top; a real backdrop click closes only it, then Escape
  closes the first.
- **Toasts:**
  - the card renders in the bottom-right corner;
  - hovering holds it past its duration;
  - after the pointer leaves, it is removed **by its own `max-height` exit transition**,
    observed as a `transitionend`, not by the 520 ms floor.

**Negative control** (`m10.mjs --control`, run by the M10 rules): rdd's defect, where closing a
dirty tab discards the edits without asking, modelled by making `confirmDiscard` answer yes
before anything is shown. It is rejected: "tab ×: closing a dirty panel did not ask".

## Findings

1. **A caller could spoof a docked panel's `panelId` (an M4 defect in ndd, not inherited).** The
   panel host applied the injected id *first* and the caller's inputs after it, so
   `openPanel(…, { inputs: { panelId: 'x' } })` won. vdd's "can never override the injected id"
   test caught it on its first run. The id now goes last and is never read from caller inputs,
   on creation and on update. An M10 rule pins the order.
2. **N9: one Escape could close a modal and a drawer.** vdd's answering modal calls
   `stopPropagation()`, which does not stop other `document` listeners. A drawer opened *after*
   a modal listens after it, and a guard-less close is synchronous, so the stack is empty by the
   time the drawer looks. ndd marks the event handled with `preventDefault()`.
3. **N8: D14 in Angular.** There is no synchronous effect, and `closePanel` publishes
   `panel:activated` (with `previous` = the closing panel) before `panel:closed`. The panel's
   component is destroyed only when the host next reacts, so a subscription sees its own
   deactivation first. Measured, not assumed: the test asserts the order, the destroy hook, and
   that an effect does *not* run.
4. **The shared host first read its `instance` input while being constructed** (NG0950). Inputs
   are not set yet then. The panel context's `id` is now a getter, and `MODAL_REF` is a factory,
   both resolved when the content, created after the inputs, injects them.
5. **The browser gate's first toast-exit check could not tell the transition from the floor.**
   Both finished under its threshold. It now observes the `transitionend` directly.
6. **Lint:** the modal backdrop's `(click)` is a pointer-only affordance whose keyboard
   equivalents are Escape and the ×, so it is `aria-hidden="true"`. That satisfies both template
   accessibility rules with no suppression.
7. **The M10 rule "no host carries its own Escape handler" first matched a template comment.**
   Its source reader stripped JS comments but not the HTML comments inside templates, and the
   backdrop's comment mentions Escape. The reader now strips both. A real handler is still
   caught, whether as `(keydown.escape)` or as `'Escape'` in code.
