# M11 — Panel overlay, panel toolbar, floating widgets, stretch · **PASS**

**Gate:** `npm run gate -- M11` (standing gate, M11 rules, browser gate). 756/756 unit tests.

## What exists

- **`<ndd-panel-overlay>`** wraps a panel's content. It provides **one signal store**, scoped to
  that panel (its toolbars, widget stacks and z-order), where rdd used three React contexts.
  It shows the four drop zones while a widget is being dragged, and renders managed widgets.
- **`<ndd-panel-toolbar position>`**, with `variant`, `buttonVariant` and `buttonSize`:
  - it claims its edge's inset and re-measures with a `ResizeObserver` in an
    `afterRenderEffect`;
  - it releases the inset on cleanup;
  - it inlines only its position (D12).
- **`<ndd-floating-widget>`:** docked to a corner, dragged free, dropped onto a corner, or
  stretched across either axis.
  - **`[(open)]`** and **`[(placement)]`** are models; anchor and stretch are one placement,
    written in one place.
  - The handles offered follow the anchor and reading direction.
  - A press does not undock; only a drag past the threshold does.
  - Resize is clamped to the toolbar band, and resize-to-stretch snaps with hysteresis.
  - A block-stretch overlap gives a dev warning.
- **`injectFloatingWidgets()`**: `openIds`, `open`, `close`, `closeAll` and `isOpen`, for
  widgets whose existence is data. The overlay owns each managed widget's placement, so a gesture
  survives unrelated renders (vdd 1.0.1's PO31–PO35).
- **Toolbar controls:**
  - `<ndd-toolbar-button>` has no `click` output; the native click bubbles and does nothing
    while disabled.
  - `<ndd-toolbar-toggle [(active)]>`.
  - `<ndd-toolbar-separator>`, `…-spacer`, `…-item`, `…-center`.
  - **`<ndd-toolbar-search>`** is debounced; its `search(query, signal)` receives an
    `AbortSignal`, a superseded result is discarded, the dropdown is portalled, and the output
    is `(resultSelect)` because `select` is a DOM event.
- `ToolbarPosition` has one definition, shared by the strip toolbar and the panel toolbar.

## Browser gate (real Chrome, zoneless **and** zone.js)

A port of vdd's M11 gate, on a playground `overlay` panel: toolbars on all four edges, a card, a
full-width strip and a free widget, driven through `window.__overlay`.

- **D5:** all eight handles of a free widget are hit by `elementFromPoint` at their centre and
  one pixel inside each edge.
- **Corner:** a press on the visible rounded corner reaches the handle, and a 60×40 drag grows
  the widget by 60×40.
- **Stretch tracks:** narrowing the panel by dragging the grid divider narrows the strip by the
  same amount, and it sits exactly inside the measured toolbar band plus gutters.
- **Stacking:** the strip and a corner card on the same edge never overlap; the upper one clears
  the lower's full height plus 8 px.
- **Toolbar:** a docked card resized towards the bottom toolbar grows and stops at it.

**Negative control** (`m11.mjs --control`, run by the M11 rules): rdd's handles at `-4px`. It is
rejected on every handle probe, the visible corner, the corner drag and the toolbar clamp.

## Findings

1. **A custom-element host is `display: inline`.** vdd's overlay root was a `<div>`, so its rule
   never declared `display`. As `<ndd-panel-overlay>` it was inline, and an inline box reports
   `clientWidth` 0. Every widget inside therefore measured a container of nothing, and every
   free resize clamped to `MIN_W`×`MIN_H`. The first browser run's corner drag *shrank* the
   widget by exactly 100×90. jsdom could not see it, since the unit suite stubs geometry. The
   fix is `.ndd-panel-overlay-root { display: block }`, and M11 rule 10 now requires a `display`
   for every host that replaced a vdd `<div>`.
2. **N10: `model()` is not "controlled without a listener".** vdd's PO24 binds `placement`
   without a listener and asserts the widget never self-applies a gesture. An Angular model is
   locally writable: a one-way binding seeds it and follows the parent's changes, but does not
   freeze it. The Angular way to veto a gesture is to answer `(placementChange)` with the
   parent's own value, which re-syncs the widget. PO24 asserts that. This holds for every model
   in the library and is recorded as N10.
3. **The managed-placement bug vdd shipped in 1.0.0 cannot occur here as written.** An Angular
   input re-syncs only when the bound value changes, and the overlay binds the store's own
   record, which is replaced exactly when the widget reports. PO31–PO35 pass unchanged.
4. **Lint** rejected `role="option"` without `aria-selected` on the search results. Those roles
   were my addition (vdd has none) and implied a listbox keyboard model that does not exist, so
   the results are plain buttons again.
5. **Type:** `OverlayStacks` now matches the core's `stackOffset` (mutable arrays in a readonly
   record), and `undock` builds its record explicitly rather than through `fromEntries`.
